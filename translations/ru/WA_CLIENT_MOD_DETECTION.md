# WhatsApp Обнаружение модифицированных клиентов — Full RE Report
**Версия:** 2.26.41.6 | **Дата:** 2026-11-01
**Область:** обнаружение на стороне клиента неофициальных/модифицированных Android-клиентов (репаки семейства GB WhatsApp, хук-модули Xposed/LSPosed, такие как WaEnhancer, переподписанные APK) — единственная найденная специализированная эвристика для модов (`is_whatsapp_plus_user`), поиск артефактов хук-фреймворков (Xposed/Frida/Substrate), что клиент делает с телеметрией подписи/источника установки/root, уже описанной в `WA_CLIENT_INTEGRITY.md`, обработка UI бана WFAC присланных сервером причин бана, и поверхность атаки, на которую, как известно, нацелен сторонний хук-модуль (WaEnhancer) внутри процесса хоста

---

## 1. Обзор

Этот отчёт посвящён **обнаружению модификаций/подделки**, а не аттестации аккаунта. Аттестация Keystore, Play Integrity, WASafe, самопроверка подписи (WAM **6251**) и флаг источника установки (WAM **10255**) полностью документированы в [`WA_CLIENT_INTEGRITY.md`](WA_CLIENT_INTEGRITY.md); этот отчёт только указывает их вклад в обнаружение модов и не повторяет их механику.

| Механизм | Обнаруживает | Передаётся как | Найденное применение |
|-----------|---------|-------------|--------------------|
| `is_whatsapp_plus_user` (рефлективная проверка класса) | Сторонний клиент, в который встроена библиотека сбора крашей ACRA | поле телеметрии `wam_daily`; строка `diagnostic` в contact-us (`nw-wap`) и отладочном отчёте (`NW-WAP-1`) | нет |
| Самопроверка подписи приложения (`AbstractC38241gg` / `C27965CCj`) — см. отчёт по целостности §5 | Переподписанный/репакованный APK (сертификат подписи ≠ встроенному значению WhatsApp) | общий атрибут WAM **6251** | нет |
| Флаг источника установки (`CHH`) — см. отчёт по целостности §5.4 | Установка сайдлоадом / не через Play | WAM **10255**, `install_source_official` | только маршрутизация загрузки модулей, без блокировки |
| Флаги root / эмулятора / custom-ROM (`C00L`, `Cdt`) — см. отчёт по целостности §6 | Рутованное или эмулируемое устройство (частый фактор, облегчающий моды, но не признак мода сам по себе) | `wam_daily` | нет |
| Строки-артефакты хук-фреймворков (Xposed, Frida, Substrate, LSPosed, TracerPid) | — | — | **не найдено** в этой сборке (§3) |
| Самопроверка контрольной суммы native-библиотеки / dex | — | — | **не найдено** в этой сборке (§3) |
| UI бана WFAC (`WfacBanActivity`) | — | отображает отправленные сервером `ban_violation_type` / `ban_violation_source` / `ban_violation_reason` | решение сервера, непрозрачно для клиента (§5) |

Ни в одном месте декомпилированного клиента не найдено кода, который отказывается запускаться, ухудшает функцию или блокирует действие из-за чего-либо из перечисленного выше. Каждый найденный механизм — это **телеметрия**, что согласуется с выводом, уже сделанным для целостности аккаунта.

## 2. Единственная специализированная эвристика для модов: `is_whatsapp_plus_user`

### 2.1 Что проверяется

Три независимых места, каждое выполняет **одну и ту же рефлективную проверку**, а не вызывает общий хелпер:

```smali
; smali_classes7/X/Cdt.smali, method C4k (fills LX/0Fp; = wam_daily event)
const-string v0, "org.acra.ACRA"
invoke-static {v0}, Ljava/lang/Class;->forName(Ljava/lang/String;)Ljava/lang/Class;
; ClassNotFoundException -> false, success -> true
iput-object v0, p1, LX/0Fp;->A0W:Ljava/lang/Boolean;   ; -> wam_daily.is_whatsapp_plus_user
```

```java
// C1Z.java (contact-us diagnostics)
try { Class.forName("org.acra.ACRA"); sbA0m.append("nw-wap "); } catch (ClassNotFoundException unused) {}

// C10V.java (debug report builder)
try { Class.forName("org.acra.ACRA"); sb10.append("NW-WAP-1 "); } catch (ClassNotFoundException unused2) {}
```

| Параметр | Значение | Уровень |
|------|-------|------|
| Проверка | `Class.forName("org.acra.ACRA")` завершается успешно (класс присутствует в classpath) | found |
| Имя поля | `is_whatsapp_plus_user` (`LX/0Fp;->A0W`), событие `wam_daily` | found |
| Приёмники | телеметрия `wam_daily`; строка `diagnostic` в contact-us (`nw-wap `); текст отладочного отчёта (`NW-WAP-1 `) | found |
| Обоснование | ACRA (`org.acra`) — сторонняя библиотека сбора крашей; стандартный WhatsApp её не включает. Исторически встраивалась репаками семейства "WhatsApp Plus" для собственной телеметрии крашей (`inferred`: имя поля — это собственный выбор названия WhatsApp, а не значение, считанное из мода) | found (проверка) / inferred (смысл названия) |
| Пробел декомпиляции | сам `Cdt.java` не декомпилировался (существует только соседний `CDT.java`); проверка прочитана из smali | found |

### 2.2 Чего эвристика НЕ делает

- Ни в одном месте декомпилированного клиента не существует allowlist/denylist имён пакетов модов (`com.gbwhatsapp`, `com.yowhatsapp`, `com.fmwhatsapp`, `com.wmods.wppenhacer`, …) — ни одна из этих строк не встречается в `java_src` или `smali*`.
- Проверка — это один рефлективный поиск класса, а не проверка подписи, хэша или поведения. Мод, который просто не включает `org.acra.ACRA` (или переименовывает/шейдит класс), обходит её без труда; этот отчёт не утверждает иного.
- Все три приёмника — это текст диагностики/телеметрии и ежедневное аналитическое событие. Не найдено ветвления, которое читает `A0W`/`is_whatsapp_plus_user` и изменяет поведение клиента.

| `/proc/self/status` (4 совпадения, `KGi`/`KGw`/`KH8`/`KGp`) | — | читатели статистики памяти (вероятно, сбор `VmRSS` для диагностики); парсинга `TracerPid` там не найдено |

**Исправление формулировки одной из прежних исследовательских заметок:** более ранняя заметка статического анализа описывает WaEnhancer как «именно тот тип модифицированного/неофициального клиента, на который нацелена система целостности стандартного приложения», но не утверждает, что стандартное приложение обнаруживает его по имени — это прочтение подтверждается здесь: в 2.26.41.6 нет кода обнаружения, специфичного для WaEnhancer, GB или Xposed. Единственный сигнал на стороне клиента, который сработал бы при установке WaEnhancer, — это общая проверка ACRA `is_whatsapp_plus_user`, и только если модуль (или одна из встроенных зависимостей) случайно поставляется с этим классом — не подтверждено ни в ту, ни в другую сторону конкретно для WaEnhancer (`unknown`).

Это дополняет `WA_CLIENT_INTEGRITY.md` §6.4, где CRC dex/ресурса было отмечено как «не исчерпывающе проверено» — теперь проверено и всё равно не найдено.

## 4. Серверные последствия, видимые на стороне клиента

### 4.1 UI бана WFAC

`WfacBanActivity` (`com.whatsapp.waffle.wfac.p191ui`) считывает три переданных сервером extra и отображает их; причину она не вычисляет:

```java
int violationType   = getIntent().getIntExtra("ban_violation_type", -1);
String violationReason = getIntent().getStringExtra("ban_violation_reason");
int violationSource  = getIntent().getIntExtra("ban_violation_source", -1);
```

| Параметр | Уровень |
|------|------|
| `ban_violation_type` / `ban_violation_source` — непрозрачные целые числа; на стороне клиента не найдено enum, сопоставляющего их с именованными причинами (например, "modified client") | found (absence) |
| `ban_violation_reason` — произвольная текстовая строка, предположительно шаблонизированная на сервере | found |
| Не найдено кода, связывающего какой-либо из сигналов обнаружения из §1–§3 (`is_whatsapp_plus_user`, несовпадение подписи, root, источник установки) со значением `ban_violation_*` | found (absence) |

Полная конечная машина состояний бана, GraphQL (`BizIntegrityQuery`), уровни доверия и XMPP stanza-ошибки описаны в [`WA_BAN_SYSTEM_DEEP_EN.md`](WA_BAN_SYSTEM_DEEP_EN.md); этот отчёт не повторяет это содержимое. Использует ли сервер какую-либо телеметрию из §1 (несовпадение подписи, `is_whatsapp_plus_user`, root) как входной сигнал для бана, **unknown** — это серверная сторона, статически не наблюдаемая, тот же вывод, что и в `WA_CLIENT_INTEGRITY.md` §13.

### 4.2 Блокировка функций

Не найдено ветвления на стороне клиента, отключающего функцию на основании сигналов из §1. Единственная «блокировка», наблюдаемая во всей области целостности/обнаружения модов, — это throttling самих запросов аттестации/токенов (ab-props, документировано в отчёте по целостности) — не реакция на обнаружение мода.

## 5. Поверхность атаки: на что нацелен хук-модуль (WaEnhancer, `com.wmods.wppenhacer`)

Этот раздел описывает другую сторону границы — что типичный модуль Xposed/LSPosed хукает внутри процесса хоста — чтобы обозначить, что должно было бы покрывать (в основном отсутствующее) обнаружение на стороне клиента. Источник доказательств: артефакты, оставленные установкой, модифицированной WaEnhancer, в захваченном тестовом каталоге `wa-data-root/` (`Protocols/waenhancer-mod/info.md`), а не статический анализ самого APK WhatsApp. Уровни указаны так, как записаны там.

| Возможность | Механизм | Уровень |
|------------|-----------|------|
| Доставка | модуль Xposed/LSPosed, выполняющийся **внутри** процесса `com.whatsapp` (не отдельное приложение, не репак) | found |
| Работа с обфускацией | runtime "Unobfuscator": разрешает обфусцированные имена классов/методов WhatsApp при запуске модуля и кэширует разрешённые хендлы (`UnobfuscatorCache.xml`, `UnobfuscatorCacheStrings.xml`), ключом служит собственное имя версии WhatsApp, так что кэш сбрасывается при обновлении любой из сторон | found |
| Скрытие присутствия ("ghost mode") | хукает методы, связанные с присутствием; настройка хранится в `WaGlobal.xml` (`ghostmode`) | found (artifact) |
| Anti-revoke / anti-read-receipt | перехватывает код удаления-для-всех и отметок о прочтении; хранит теневые копии в собственных хранилищах (`com_waenhancer_message_history.db`, и `MessageHistory.db` на базе Room — сам WhatsApp не использует Room для хранения сообщений) | found |
| Видимость сырого протокола | `StanzaLogger.logStanza(...)` записывает исходящие/входящие XMPP stanza в текстовый файл (`wae_stanzas.txt`) — то есть модуль снимает данные с собственного пути отправки/приёма stanza клиента после того, как слой Noise/E2E уже их расшифровал | found |
| Учёт хуков | диагностика на каждый запуск, логирующая количество хуков (`devtrace_logs/*.jsonl`, `eventType:"hook_config_loaded"`, `payload.hookCount`) | found |
| Границы охвата | хукает только слой Java/UI; не заменяет native-криптографию или транспорт Noise/chatd (хранилище axolotl/Signal, постквантовые prekeys, keystore, native-код OHAI/OPAQUE/WAFFLE не затронуты) | inferred |

В сочетании с §3: у стандартного клиента нет кода, который перечисляет загруженные модули Xposed/LSPosed, сканирует собственную память процесса на хук-трамплины или проверяет `TracerPid`/`/proc/self/maps` на внедрённые библиотеки. Единственное, что стоит между этой поверхностью атаки и обнаружением, — это единственная общая проверка класса `is_whatsapp_plus_user` (§2), которая нацелена на библиотеку сбора крашей, а не на хук-фреймворк.

## 6. Ошибочные случаи / тонкости

| Симптом | Причина | Примечание |
|---------|-------|------|
| `is_whatsapp_plus_user = true` в `wam_daily` без дальнейшего эффекта на клиенте | `org.acra.ACRA` разрешается в classpath | только телеметрия, так и задумано |
| `diagnostic` содержит `nw-wap` / `NW-WAP-1` в contact-us или отладочных отчётах | та же проверка ACRA, другой приёмник | текст для потока поддержки, не блокировка |
| На экране бана WFAC нет причины помимо числового кода | у `ban_violation_type`/`ban_violation_source` нет enum на стороне клиента | контролируется сервером, статически не разрешается |
| Поиск "Xposed"/"Frida" ничего не даёт | верно — эта сборка не содержит обнаружения хук-фреймворков | не пробел декомпиляции для этих конкретных строк (поиск по всему дереву) |
| Установка WaEnhancer меняет поведение сообщений/отметок о прочтении без лога на стороне WhatsApp | WaEnhancer хукает слой Java до того, как собственная телеметрия WhatsApp может наблюдать исходный вызов | ожидаемо с учётом охвата §5 |

## 7. Ключевые различия

| Не путать | Факт |
|-----------------|------|
| `is_whatsapp_plus_user` и allowlist клиентов-модов | одна рефлективная проверка класса стороннeй библиотеки; списка имён пакетов модов не существует |
| Обнаружение модов/подделки (этот отчёт) и аттестация аккаунта (`WA_CLIENT_INTEGRITY.md`) | разные задачи: этот отчёт — об обнаружении *модифицированного бинарника/runtime клиента*; отчёт по целостности — об *аттестации подлинного устройства/ключа* перед сервером — они пересекаются только в том, что оба являются телеметрией, а не принуждением |
| UI бана WFAC (`WfacBanActivity`) и логика принятия решения о бане | activity отображает присланные сервером коды/строки; она не принимает решение и не вычисляет причину бана |
| Снятие данных через `StanzaLogger` в WaEnhancer и взлом E2E-шифрования | модуль читает stanza внутри уже расшифровавшего их процесса клиента; саму криптографию Signal/Noise он не атакует |
| телеметрия `safety-net-attestation` / подписи / источника установки | она существует и документирована в `WA_CLIENT_INTEGRITY.md`; этот отчёт не добавляет новой механики для неё, только указывает, что ничто из неё ничего не блокирует |
| «Не найдено» в этом отчёте | означает отсутствие в декомпилированных Java/smali/строках именно этой сборки (2.26.41.6); это не утверждение о серверном обнаружении, которое статически не наблюдается |

## 8. Полный сквозной поток

```
[Device boots WhatsApp, possibly under a hook module or with a bundled crash-reporter lib]
    │
    ▼
[Cdt.C4k / C1Z / C10V]  Class.forName("org.acra.ACRA")
    │  success ──► is_whatsapp_plus_user = true ─► wam_daily
    │  success ──► "nw-wap" / "NW-WAP-1" ─► contact-us / debug-report text
    │  (no further branch — nothing reacts to this value in the client)
    ▼
[AbstractC38241gg / C27965CCj]  signature self-check → WAM 6251   (see WA_CLIENT_INTEGRITY.md §5)
[CHH]                           install-source flag  → WAM 10255  (see WA_CLIENT_INTEGRITY.md §5.4)
[C00L / Cdt]                    root / emulator / custom-ROM     → wam_daily  (see WA_CLIENT_INTEGRITY.md §6)
    │
    ▼
[WA telemetry backend]  (server-side use of all of the above: unknown, not observable)
    │
    ▼
[If the server bans the account]
    │  ban_violation_type / ban_violation_source / ban_violation_reason sent as intent extras
    ▼
[WfacBanActivity]  displays the server's values verbatim — no client-side cause mapping
```
