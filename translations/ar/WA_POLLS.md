# WhatsApp الاستطلاعات — Full RE Report
**الإصدار:** 2.26.41.6 | **التاريخ:** 2026-11-01
**النطاق:** عائلة رسائل الاستطلاع (`pollCreationMessage` إلى `pollCreationMessageV6`، `pollCreationOptionImageMessage`، `pollAddOptionMessage`، `pollUpdateMessage`، `pollResultSnapshotMessage`/`V3`)، تاريخ الإصدارات ومنطق اختيار الإرسال/الاستقبال، التحقق من صحة الإنشاء والحدود، ربط خيار الصورة بالاستطلاع، منطق اختيار التصويت ونموذج الخصوصية، التصويت المتعدد مقابل التصويت المفرد، تعديل الاستطلاع، أخذ لقطة النتائج عند إعادة التوجيه، أعلام الميزات

---

## 1. ما هو

الاستطلاع هو كائن فرعي من `Message` (`PollCreationMessage`، يُعاد استخدامه بلا تغيير عبر ستة حقول علوية مرقّمة) يحمل سؤالًا وقائمة خيارات وحدًا أعلى للاختيار وإعدادات اختيارية للاختبار (quiz) / وقت الانتهاء / الظهور. الأصوات (`pollUpdateMessage`) والخيارات المضافة (`pollAddOptionMessage`) والتعديلات (`secretEncryptedMessage`) هي رسائل تابعة منفصلة مرتبطة بمعرّف رسالة الإنشاء ومشتقة من سرّها الخاص بالرسالة؛ ذلك التشفير (حالات استخدام HKDF، AES-GCM، AAD، إعادة محاولة الهوية) مُغطّى في [WA_MESSAGE_SECRETS.md](./WA_MESSAGE_SECRETS.md) ولا يُكرَّر هنا. يغطي هذا التقرير طبقة نوع الرسالة: أي حقل يحمل ماذا، وكيف يختار العميل بينها، والتحقق والحدود، وما تفعله المعالِجات الخاصة بالاستطلاع بالحمولات بعد فك التشفير. كل النتائج تحليل ساكن لتطبيق APK المفكَّك 2.26.41.6 (مصادر Java تحت `java_src/`، بالإضافة إلى `res/values/strings.xml`)؛ لم يُلتقط شيء على الشبكة. المستويات: **found** = قُرئ في الشيفرة/الموارد، **inferred** = مستنتج من الشيفرة، **unknown** = غير محلول.

## 3. تاريخ الإصدارات

### 3.1 الحقل المستخدم للإرسال (found، `F2N.A00`/`A02`)

```text
pollType == QUIZ (correct answer set)              -> pollCreationMessageV5
chat is a community default-subgroup (group_type 3) -> pollCreationMessageV2
else:
  hideParticipantName / endTime / allowAddOption set -> pollCreationMessageV6
  none of those set                                   -> pollCreationMessageV3
```

`pollCreationMessageV4` لا يُعبَّأ أبدًا من مسار الإرسال المقروء في هذا الفحص؛ يظهر فقط عند الاستقبال (§3.3). فحص المجتمع يعيد استخدام نفس المُسنَد `group_type == 3` المستخدم في احتياط التفاعل النصي الصريح في [WA_MESSAGE_SECRETS.md](./WA_MESSAGE_SECRETS.md) §6.2 (`C0GQ.A0A(chat) == 3`، مضبوط من `isDefaultSubgroup_`)؛ السبب في أن استطلاع المجموعة الفرعية الافتراضية يحصل على فتحته المُرقّمة الخاصة بدلًا من V3/V6 ليس مُفسَّرًا في الشيفرة المقروءة هنا (inferred: ترتيب تاريخي للطرح، بما أن رقم حقل V2 هو الأدنى بين المجموعة الموسّعة).

فعمليًا: **V3** هي الفتحة الحالية لاستطلاع عادي متعدد/مفرد الاختيار بلا إضافات، و**V6** هي الحالية لاستطلاع يستخدم وقت الانتهاء أو إخفاء أسماء المصوّتين أو إضافة الخيارات، و**V5** هي الحالية للاختبارات، و**V2** نسخة خاصة بالمجموعة الفرعية للمجتمع من نفس الشكل الأساسي. **V1** (الحقل غير المُرقّم 49) و**V4** لا يختارهما المُرسل في هذا الإصدار.

### 3.2 `pollCreationMessageV4` = غلاف متوافق مستقبليًا (found، `F2N.CM7`)

نوع proto لـ V4 هو `FutureProofMessage` (`BD2`، حقل واحد `message` = رسالة `Message` داخلية). عند الاستقبال، عندما تكون فتحة V4 معبَّأة، يفكّ العميل غلاف `BD2.message_` ويقرأ حقل `pollCreationMessage` (49) للرسالة الداخلية تلك على أنه `PollCreationMessage` الفعلي. هذا غلاف احتياطي حقيقي، لا حقل ميت: مُرسل يحتاج إلى بثّ نسخة استطلاع أحدث/غير مُعرَّفة يمكنه تغليف استطلاع أساسي (بشكل الحقل 49) داخل V4 بحيث لا تزال العملاء الأقدم — التي تفهم فقط فكّ `FutureProofMessage` العام، لا الفتحة الأحدث — تعرض استطلاعًا عاديًا. لا يوجد مسار شيفرة في هذا الفحص يُعبّئ V4 عند الإرسال، فهذا موجود للتوافق الأمامي/الخلفي بين إصدارات العميل، لا لأي شيء يبثّه عميل 2.26.41.6 نفسه (inferred).

### 3.3 اختيار الاستقبال والتنزيل (found، تقريبي؛ فقد المفكِّك بنية بعض الفروع)

يفحص `F2N.CM7` حقول bitfield لـ `Message` بالترتيب V1 ← V2 ← V4 ← V5 ← V6 ← احتياط-V3 ويحلّل أي حقل مُرقَّم معبَّأ إلى نفس المُحقِّق (`F2N.A01`، §4). ثلاثة أعلام تضبط قبول حقول V6 الإضافية عند الاستقبال؛ عندما يكون أحد الأعلام مُعطَّلًا يُنزَّل الاستطلاع (يُحلَّل كبديل عام متوافق مستقبليًا بدلًا من فقاعة استطلاع) لا يُرفض تمامًا:

| الحقل الإضافي | العلم | التأثير عند تعطيل العلم |
|-------------|------|--------------------------|
| `endTime` | AB int **24884** (`receivingEnabled`) | يُسجَّل `poll downgraded to FMessageFuture (receiving disabled)`، لا يُعرَض كاستطلاع |
| `hideParticipantName` | AB int **24885** | تنزيل (قطبية الفحص الدقيقة غير محلولة بالكامل من تدفق التحكم المفكَّك) |
| `allowAddOption` | AB int **25758** | تنزيل |

لم يتسنَّ إعادة بناء تداخل هذه الشروط الثلاثة بالكامل (يُقرِّر JADX وجود كتل مكرَّرة/غير قابلة للوصول في `F2N.CM7`)؛ الأعلام والنتيجة النهائية (التنزيل) مُثبَتة (found)، لكن التركيبة المنطقية الدقيقة مُستنتجة (inferred).

### 3.4 بوابة محتوى الصورة

`pollContentType = IMAGE` تُحتَرم فقط على مسار تحليل V3/V5 عندما يكون bit حقل `pollContentType` مضبوطًا؛ إذا كان مضبوطًا لكن القيمة ليست `IMAGE`، تُرفض الرسالة (`return null`، تسقط إلى المحلِّل العام) لا أن تُعامَل بصمت كنص.

## 4. التحقق من صحة الإنشاء (found، `F2N.A01`)

مُحقِّق واحد مشترك بين جميع حقول الإنشاء المُرقَّمة. يُطلق استثناءً، رمز الخطأ **11** إلا حيث يُذكر غير ذلك:

| الفحص | القاعدة | نص الخطأ |
|-------|------|--------------|
| وجود الاسم | bit حقل `name` يجب أن يكون مضبوطًا | `poll_creation_missing_name` |
| طول الاسم | 1–5000 حرف (إلا إذا تجاوزه سياق تحليل متسامح، §4.1) | `poll_creation_invalid_name` |
| إجابة الاختبار الصحيحة | إذا كان `pollType=QUIZ`، bit حقل `correctAnswer` يجب أن يكون مضبوطًا | `poll_creation_missing_correct_answer` |
| وجود الخيارات | على الأقل خيار واحد، إلا إذا انطبق تجاوز "صفر خيارات" (§4.1) | `poll_creation_missing_options` |
| عدد الخيارات (الحد الأدنى) | ≥ خياران (0 تحت التجاوز) | `poll_creation_invalid_options_count` |
| عدد الخيارات (الحد الأعلى) | ≤ `min(AB int 1408, 12)` — 12 سقف ثابت على جانب العميل بصرف النظر عن قيمة الخادم | `poll_creation_invalid_options_count` |
| طول اسم الخيار | 1–2500 حرف لكل خيار | `poll_creation_invalid_option` |
| اسم الإجابة الصحيحة | إذا كان اختبارًا، `correctAnswer.optionName` يجب أن يكون غير فارغ | `poll_creation_missing_correct_answer_name` |
| خيارات مكرَّرة | أسماء الخيارات يجب أن تكون فريدة | `poll_creation_duplicate_options` |
| خيارات مكرَّرة بعد الحذف المحيطي | تحت علم AB **25758**، الأسماء بعد حذف الفراغات المحيطة يجب أن تكون فريدة أيضًا | `poll_creation_duplicate_trimmed_options` |
| تطابق الإجابة الصحيحة مع خيار | اسم إجابة الاختبار الصحيحة يجب أن يساوي اسم خيار واحد | `poll_creation_unmatched_correct_answer` |
| وجود عدد الاختيار | bit حقل `selectableOptionsCount` يجب أن يكون مضبوطًا | `poll_creation_missing_selectable_options_count` |
| نطاق عدد الاختيار | `0 <= selectableOptionsCount <= options.size()` (أو `<= min(1408,12)` تحت التجاوز) | `poll_creation_invalid_selectable_options_count` |

### 4.1 تجاوز "صفر خيارات" / التجاوز المتسامح (found مسار الشيفرة، الدلالة مُستنتجة)

قيمة منطقية محلية (`z`) محسوبة من AB bool **37909**، لا تُستشار إلا عندما يساوي عدّاد سياق تحليل داخلي 1، تُخفِّف الحد الأدنى لعدد الخيارات إلى 0 وتوسِّع سقف عدد الاختيار إلى الحد الخام `min(1408,12)` بدلًا من `options.size()`. قيمة سياق التحليل التي يقابلها ذلك (استقبال عادي مقابل مسار استيعاب آخر، مثل مزامنة السجل التاريخي) لم تُحلّ؛ هذا مُسجَّل كـ found-but-unexplained لا كميزة "استطلاع بلا خيارات" مُؤكَّدة للمستخدم.

### 4.2 تجاوز مزامنة السجل التاريخي / الاسم المتسامح

علم سياق منفصل (`c33371Eg0.A0W`) يقصِّر الدائرة في فحص طول الاسم وكذلك (على نحو مكافئ، في `F39`، §9) فحص طول اسم لقطة النتيجة، ويقبل السلسلة الخام دون فحص. يتوافق مع مسار تحليل من مصدر موثوق (مثل إعادة استيراد السجل التاريخي محليًا) لا استقبال شبكي عادي؛ غير مؤكَّد بشكل مستقل.

## 5. خيارات استطلاع الصور: `pollCreationOptionImageMessage`

### 5.1 البنية والربط (found)

`pollCreationOptionImageMessage` (الحقل 90) يغلِّف `ImageMessage` مرفوعة عادية داخل `FutureProofMessage` — الصورة **ليست** مضمَّنة في `PollCreationMessage.Option`. تُرسَل كل صورة خيار كرسالة فرعية خاصة بها، مرتبطة بالاستطلاع (الذي لم يُرسَل بعد) عبر `MessageContextInfo.messageAssociation`، نوع الربط `MEDIA_POLL = 6` (`AnonymousClass122.MEDIA_POLL`؛ هذه قيمة enum لهذا الإصدار — كانت في إصدار سابق 7، والقيمة الرقمية غير ثابتة بين الإصدارات ويجب إعادة قراءتها في كل إصدار). المساعد الخاص بجانب الإرسال "MediaPollAssociationProvider" (في `C20M`) يعدّ صفوف `message_association` لمعرّف صف الاستطلاع الأصل ونوع الربط `6`؛ عندما يبلغ العدد عدد الخيارات، تُعتبر كل صور الخيارات مرفوعة ويواصل العميل إرسال الاستطلاع نفسه بـ `pollContentType = IMAGE`.

### 5.2 ملخّص (hash) الخيار للخيارات ذات الصور (inferred، منقول من إصدار سابق، لم يُستنتج سطرًا بسطر في 2.26.41.6)

بالنسبة للخيارات النصية العادية يُترك حقل `optionHash` على السلك فارغًا؛ الملخّص الوحيد المحسوب لخيار نصي عادي هو ملخّص البحث المحلي `C13J.A00`:

```text
optionHash(text option) = Base64(SHA-256(UTF8(optionName)))
```

(مُؤكَّد مباشرة في 2.26.41.6، §9.1 — هذه القيمة المستخدمة لمطابقة اختيارات التصويت، لا حقل `optionHash` في proto). بالنسبة لخيارات **الصور** يُعبَّأ حقل `optionHash` في proto؛ تتبُّع إصدار سابق لتسلسل الإرسال وجد أنه يجمع ملخّص اسم الخيار مع `fileSha256` للصورة المرفوعة:

```text
nameHash   = lowerHex(SHA-256(UTF8(optionName)))
imageHash  = base64(imageMessage.fileSha256)
optionHash = lowerHex(SHA-256(UTF8(nameHash + imageHash)))
```

لم تُعَد التحقّق من هذه الصيغة مقابل شيفرة 2.26.41.6 في هذا الفحص (الفئة التي تحسبها لم تُعثر عليها)؛ تُنقَل كـ inferred ويجب إعادة فحصها قبل الاعتماد عليها.

## 6. `pollAddOptionMessage` (`C30556DRc`، الحقل 121)

### 6.1 الحقول (found)

`pollCreationMessageKey` **1** (`MessageKey`)، `addOption` **2** (`PollCreationMessage.Option`)، `metadata` **3** (`PollUpdateMessageMetadata`، نفس شكل بيانات التصويت، §7).

### 6.2 الإرسال (found، `F2L.ADr`)

يبني `Option` واحدًا من الاسم الجديد (وملخّصه بالنسبة لاستطلاعات الصور)، ويرفق مفتاح الاستطلاع الأصل، ويحلّ — للمحادثات الفردية، عندما لا يكون سياق تعديل — هوية المُرسل عبر حدود LID/PN بنفس الطريقة التي تستخدمها طبقة سرّ الرسالة لإضافات أخرى (انظر [WA_MESSAGE_SECRETS.md](./WA_MESSAGE_SECRETS.md) §6.1 الخطوة 4). الخيار المُضاف نفسه **غير** مشفَّر بالسرّ في هذه الطبقة كما تُشفَّر `pollUpdateMessage`: حمولة إضافة الخيار تنتقل كحقل رسالة عادي؛ ما يُغلَّف في `secretEncryptedMessage` (النوع `POLL_ADD_OPTION`) هو محاولة إضافة الخيار بأكملها عندما يجب أن تمر عبر خطة سرّ الرسالة (§8).

### 6.3 التحقق عند الاستقبال (found، `F2L.CM7`)

| الفحص | الخطأ |
|-------|-------|
| بوابة الميزة: AB int **25758** يجب أن يكون غير صفري | الخطأ **10017** |
| وجود `pollCreationMessageKey` | `poll_add_option_missing_poll_message_key` |
| وجود `addOption` | `poll_add_option_missing_poll_option` |
| اسم الخيار غير فارغ، ≤ 2500 حرف | `poll_add_option_invalid_option` |

الكائن المحلي الناتج يُشفَّر بالسرّ للنقل باستخدام حالة الاستخدام `Poll Add Option` (استدعاء مُؤكَّد إلى مساعد سرّ الرسالة مع `AnonymousClass122.POLL_ADD_OPTION` كوسم ربط). الخيارات المُضافة تُتابَع من أجل مطابقة الخيارات القائمة بنفس الطريقة المستخدمة لخيارات استطلاع الصور (نوع الربط `POLL_ADD_OPTION = 18`).

## 7. `pollUpdateMessage` (التصويت وبياناته الوصفية)

التشفير الكامل (حالة استخدام HKDF `Poll Vote`، AAD، AES-GCM، إعادة محاولة هوية LID/PN) في [WA_MESSAGE_SECRETS.md](./WA_MESSAGE_SECRETS.md) §3–§7؛ يغطي هذا القسم فقط ما تفعله معالِجة تصويت الاستطلاع (`DUA`، تمتد من `F2P`) بالنص الصريح.

### 7.1 مساران للإرسال/الاستقبال (found)

AB bool **6772** يختار بين:
- **مفعَّل** (الحالي): مساعد تشفير مشترك (`C33285Eeb`) يبني النص المشفَّر و`MessageKey`؛ يُعاد محاولة التصويت من زوج `(iv, payload)` مخزَّن سابقًا إن وُجد بدلًا من إعادة التشفير.
- **معطَّل** (قديم): فرع مضمَّن في `DUA` يقوم بنفس استدعاء HKDF/AES-GCM مباشرة، مشتقًا هوية المُستقبل المستهدف نفسه (LID الخاص بالمصوِّت لتصويته على استطلاعه الخاص، وإلا JID المُحلَّل لهدف التصويت).

### 7.2 حمولة التصويت: `PollVoteMessage` (`DPF`)

حقل واحد `selectedOptions` **1**، bytes مكرَّرة — كل مُدخل هو ملخّص SHA-256 لاسم خيار من 32 بايت (§9.1)، لا فهرس. `MessageAddOnPollVoteUtils` (`AbstractC33199EdC`) يتحقق من صحة الاختيار بعد فكّ التشفير:

| الفحص | القاعدة | وسم السجلّ |
|-------|------|---------|
| حجم الاختيار | ≤ 12 **و** ≤ `selectableOptionsCount` للاستطلاع (عندما > 0) | `poll_vote_invalid_options_count` |
| شكل الملخّص | كل ملخّص مُختار يُفكَّك إلى 32 بايت بالضبط | `poll_vote_invalid_option_hashes` |
| التكرار | لا ملخّص مكرَّر في تصويت واحد | `poll_vote_duplicate_option_hashes` |
| الحل | كل ملخّص مُختار يجب أن يطابق واحدًا من ملخّصات خيارات الاستطلاع المعروفة (غير المحذوفة) | يُعيد نتيجة خطأ، لا تطابق -> يُرفض التصويت |

### 7.3 وقت الانتهاء والبيانات الوصفية (found، `DUA.A01`)

تصويت تكون `senderTimestampMs` الخاصة به بعد `endTime` الاستطلاع يُرفَض (`poll_update_past_end_time`)؛ تحت AB bool **2321** يُغذِّي حدث تصويت مرفوض إضافيًا عدّاد تحليلات (`N0e`). البيانات الوصفية للتصويت `metadata` (`pollNameHash`، `lastEditStanzaId`) تُختَم عند الإرسال فقط تحت AB bool **31593**؛ عند الاستقبال، كتلة بيانات وصفية غائبة/فارغة تُسجَّل `"unstamped"` (لا تُرفض بذاتها) بينما ختم **غير مطابق** (يفحصه `C32977EZa`) يُسقِط التصويت مع `poll_update_tc_drop`. هذه البيانات الوصفية موجودة ليتمكن العميل من اكتشاف أنه يصوِّت مقابل استطلاع لم يُدرِك سجل تعديلاته بعد.

## 8. تعديل الاستطلاع (`secretEncryptedMessage`، `secretEncType = POLL_EDIT`)

تُحمَل داخل الغلاف العام `secretEncryptedMessage` (الحقل 82)، لا حاملًا خاصًا بالاستطلاع؛ انظر [WA_MESSAGE_SECRETS.md](./WA_MESSAGE_SECRETS.md) §5/§7.4 للغلاف وAAD وجدول رموز الخطأ (`poll_edit_message_stanza_invalid`، بوابة AB int **24886**، الخطأ **10016**). التحقق الخاص بالاستطلاع (`F3Y`، `SecretEncryptedMessageDeserializationValidator`) يتطلب:

- أن تكون الرسالة الداخلية من نوع FMessage **66** وأن تكون استطلاعًا قبل التعديل وبعده؛
- أن تبقى `endTime` و`hideParticipantName` و`allowAddOption` و`selectableOptionsCount` و`pollType` **بلا تغيير** بين الاستطلاع المخزَّن والمُعدَّل — فقط نص السؤال و/أو نصوص الخيارات يمكن أن تختلف؛
- مطابقة الخيارات: مع علم خاص بالمحادثة (`EOI.A01()`، المعرّف غير محلول) مُفعَّل، تُطابَق الخيارات المُعدَّلة مع سجل إعادة التسمية المخزَّن عبر مطابقة متسلسلة (تحفظ الترتيب)، تسمح بإعادة تسمية الخيارات في موضعها؛ السلوك الدقيق لفرع المقارنة غير القائم على إعادة التسمية مُستنتج (يُفقِد JADX مجددًا جزءًا من تدفق التحكم — الدالة تسقط في شكلها المفكَّك إلى `poll_edit_invalid_edits` في ذلك الفرع، وهو أمر غير محتمل أن يكون السلوك الحقيقي للعميل لتعديل لا يُغيِّر شيئًا).

نص توست `"Couldn't edit poll"` موجود في الموارد، يُؤكِّد أن تعديل الاستطلاع ظاهر للمستخدم في هذا الإصدار، لا مسار بروتوكول محجوز فقط.

## 9. آليات مطابقة التصويت الداخلية

### 9.1 ملخّص الخيار (found، `C13J.A00`)

```text
optionHash = Base64(SHA-256(UTF8(optionName)))
```

SHA-256 صِرف لنص الخيار الظاهر، بلا مادة مفتاحية. هذه القيمة المخزَّنة لكل خيار محلي (`C33283EeZ.A02`) والقيمة التي تُطابَق مقابلها مُدخلات `selectedOptions` لتصويت ما. أي تطبيق يعرف نص الخيار يمكنه حساب نفس الملخّص — خصوصية التصويت تأتي كليًا من تشفير سرّ الرسالة لحمولة التصويت (§7، و[WA_MESSAGE_SECRETS.md](./WA_MESSAGE_SECRETS.md))، لا من كون الملخّص غير قابل للتخمين.

## 11. التصويت المتعدد مقابل المفرد

`selectableOptionsCount` (الحقل 4) هو الآلية الوحيدة: تصويت باختيارات أكثر من هذه القيمة يُرفَض (§7.2). لا يوجد منطق منطقي "is multi-select" منفصل على السلك — التصويت المفرد هو ببساطة `selectableOptionsCount = 1`. واجهة الإنشاء تعرض هذا كمفتاح تبديل واحد، **"السماح بإجابات متعددة"** (نص `str425f`)؛ عند تعطيله يُستنتَج أن العميل يرسل `selectableOptionsCount = 1`، وعند تفعيله يُستنتَج أنه يرسل `selectableOptionsCount = options.size()` (لا يبدو أن واجهة المستخدم تعرض سقفًا عدديًا تعسفيًا — مُستنتج من نص مفتاح تبديل منطقي واحد، غير مؤكَّد بشكل مستقل في شيفرة واجهة الإنشاء). البروتوكول نفسه يسمح بأي قيمة `0..options.size()` (§4)، لذا فإن قيمة من جانب العميل غير 1 أو "كل الخيارات" ممكنة حتى لو لم تعرضها واجهة المستخدم القياسية. الاختبارات (quizzes) أحادية الاختيار ضمنيًا (إجابة صحيحة واحدة؛ نص ظاهر للمصوِّت "Quiz • Select one correct answer"‏، `str57a5`).

النصوص الظاهرة للمصوِّت تُؤكِّد النمطين: "Select one"‏ (`str3865`) مقابل "Select one or more"‏ (`str3866`).

## 12. `pollResultSnapshotMessage` / `V3`: لقطة عند إعادة التوجيه

### 12.1 الغرض (found، `F1A`)

إعادة توجيه استطلاع حيّ إلى محادثة أخرى **لا** يعيد توجيه الاستطلاع التفاعلي. `F1A` (أحد عدة محوِّلات "forward" تُنفِّذ جميعها نفس واجهة التحويل المستخدمة عبر أنواع الرسائل — المحوِّل المماثل للأنواع غير المدعومة يُطلق `"Cannot forward message of type: ..."`) يحوِّل الاستطلاع الحيّ (`C13J`) إلى كائن `Dd2`: نص السؤال، واسم كل خيار و**عدد أصواته المحلي الحالي**، ونوع الاستطلاع/الاختبار. هذا يُسلسَل بعدها كـ `pollResultSnapshotMessage` (استطلاع عادي) أو `pollResultSnapshotMessageV3` (اختبار) ويُعرَض بحامل عرض مخصَّص (`DWH`)، منفصل عن فقاعة الاستطلاع التفاعلية.

### 12.2 الحقول (found، `DSF`)

`name` **1** (string)، `pollVotes` **2** (repeated `PollVote` — `optionName` **1**، `optionVoteCount` **2**)، `contextInfo` **3**، `pollType` **4** (نفس enum `PollType` للإنشاء).

### 12.3 التحقق من الصحة (found، `F39`)

نفس شكل فحوصات الإنشاء: اسم 1–5000 حرف، خياران على الأقل، حد أقصى `min(AB 1408, 12)` خيارات، كل اسم خيار 1–2500 حرف. بالنسبة لنسخة **الاختبار** (`V3`)، عدّادات الأصوات تُصفَّر إجباريًا عند الإرسال — لقطة اختبار مُعاد توجيهها لا تكشف أبدًا الحصائل، فقط السؤال وقائمة الخيارات.

## 15. Baileys (الحقائق المُؤكَّدة فقط)

[WA_MESSAGE_SECRETS.md](./WA_MESSAGE_SECRETS.md) §17 يغطي من قبل الأجزاء الخاصة بالاستطلاعات من تطبيق JavaScript (`baron-baileys-v2` 1.5.17) من قراءة `src/Utils/process-message.js`، `src/Utils/reporting-utils.js`، `src/Utils/messages.js`، `src/Socket/messages-send.js`:

- اشتقاق HKDF وسلاسل حالات الاستخدام `Poll Vote`، `Event Response`، `Enc Comment`، `Enc Reaction`، `Event Edit`، `Message Edit`، `Poll Edit`، `Poll Add Option` تطابق حرفيًا سلاسل عميل Android، بما فيها AAD بشكل `id\0modifier` لـ `Poll Vote`.
- AAD، وإعادة محاولة الهوية (PN/LID)، ومعالجة السرّ المفقود (الرجوع إلى التحديث الخام غير المفكوك التشفير) تطابق سلوك Android المُوصَّف في هذا التقرير (§7) وفي [WA_MESSAGE_SECRETS.md](./WA_MESSAGE_SECRETS.md) §7.2–§7.3.
- لم يُعثر على مسار تشفير جانب الإرسال لـ `pollUpdateMessage` (أو `encReactionMessage`، `encEventResponseMessage`، `encCommentMessage`) في الملفات المقروءة — أي أن ذلك التطبيق يمكنه فكّ تشفير تصويت وارد لكن الملفات المُراجَعة لم تحتوِ على شيفرة لتشفير تصويت وإرساله.

لم يُعَد التحقّق بشكل مستقل من شيء خاص بالاستطلاعات يتجاوز ما هو مذكور هناك فعلًا في هذا الفحص (لم تُقرأ شيفرة Baileys لإنشاء الاستطلاع أو ملخّص الخيار أو تعديل الاستطلاع)؛ لا دعاوى Baileys أخرى تُقدَّم هنا.

## 18. التدفق الكامل (الإنشاء، خيار الصورة، التصويت، إعادة التوجيه)

```
[Creator]                                          [Server]                     [Participant]
   │ build PollCreationMessage                        │                              │
   │  (quiz? -> V5; community subgroup? -> V2;         │                              │
   │   extras(endTime/hide/addOpt)? -> V6; else V3)    │                              │
   │ [image poll]                                      │                              │
   │  send N × pollCreationOptionImageMessage           │                              │
   │   (messageAssociation MEDIA_POLL=6, parent key)───▶───────────────────────────▶ received,
   │  wait for all fileSha256                           │                              associated
   │  compute optionHash per option                     │                              │
   │ send pollCreationMessage* ─────────────────────────▶──────────────────────────▶ store poll,
   │                                                    │                              secret
   │                                                    │        select option(s)     │
   │                                                    │        hash = SHA256(name)  │
   │                                                    │        key = HKDF(secret,   │
   │                                                    │          pollId‖creator‖    │
   │                                                    │          voter‖"Poll Vote") │
   │                                                    │        pollUpdateMessage    │
   │◀────────────────────────────────────────────────────◀ {key, vote{ct,iv}, ts} ────│
   │ validate: end time, selection count/hash shape     │                              │
   │ decrypt, resolve hash -> known option              │                              │
   │ apply vote                                         │                              │
   │                                                    │                              │
   │ [user forwards the poll elsewhere]                 │                              │
   │ convert live poll -> Dd2 (name, per-option count)  │                              │
   │ quiz? zero the counts                              │                              │
   │ send pollResultSnapshotMessage[/V3] ───────────────▶──────────────────────────▶ static bubble,
   │                                                    │                              not interactive
```

## 19. المجهولات

|------|-------|
| القطبية الدقيقة لـ AB **24885** (قبول/تنزيل `hideParticipantName`) | بنية الفرع المفكَّكة غير كاملة |
