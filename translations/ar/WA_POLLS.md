# WhatsApp الاستطلاعات — Full RE Report
**الإصدار:** 2.26.41.6 | **التاريخ:** 2026-11-01
**النطاق:** عائلة رسائل الاستطلاع (`pollCreationMessage` حتى `pollCreationMessageV6`، `pollCreationOptionImageMessage`، `pollAddOptionMessage`، `pollUpdateMessage`، `pollResultSnapshotMessage`/`V3`)، تاريخ الإصدارات ومنطق اختيار الإرسال/الاستلام، تحقق الإنشاء وحدوده، ربط خيار الصورة في الاستطلاع، نموذج اختيار التصويت والخصوصية، التصويت المتعدد مقابل الفردي، تحرير الاستطلاع، لقطة النتيجة عند إعادة التوجيه، أعلام الميزات

---

## 1. ما هو

الاستطلاع كائن فرعي من `Message` (`PollCreationMessage`، يُعاد استخدامه دون تغيير عبر ستة حقول مُرقَّمة بإصدارات على المستوى الأعلى) يحمل سؤالاً، قائمة خيارات، سقف اختيار، وإعدادات اختيارية للاختبار/وقت الانتهاء/الظهور. التصويتات (`pollUpdateMessage`)، الخيارات المُضافة (`pollAddOptionMessage`) والتحريرات (`secretEncryptedMessage`) رسائل متابعة منفصلة مرتبطة بمعرّف رسالة الإنشاء ومُفهرَسة بسرّها الخاص بالرسالة؛ ذلك التشفير (حالات استخدام HKDF، AES-GCM، AAD، إعادة محاولة الهوية) مُغطًّى في [WA_MESSAGE_SECRETS.md](./WA_MESSAGE_SECRETS.md) ولا يُكرَّر هنا. يغطي هذا التقرير طبقة نوع الرسالة: أي حقل يحمل ماذا، كيف يختار العميل بينها، التحقق والحدود، وما تفعله معالِجات الاستطلاع الخاصة بالحمولات المفكوكة التشفير. كل النتائج تحليل ساكن لـAPK 2.26.41.6 المفكَّك (مصادر Java تحت `java_src/`، إضافة إلى `res/values/strings.xml`)؛ لم يُلتقط شيء على السلك. المستويات: **found** = مقروء في الكود/الموارد، **inferred** = مُستنتَج من الكود، **unknown** = غير محسوم.

يخزِّن العميل استطلاعاً مُحلَّلاً كـ`C13J` (نسخة صورة الاختبار `C13K`)، بخيارات كأجسام `C33283EeZ` تحمل الاسم الخام (`A04`)، ملخَّص SHA-256 محسوباً محلياً للاسم (`A02`، §9.1) و، لخيارات الصور، `optionHash` السلكي (`A08`).

## 3. تاريخ الإصدارات

### 3.1 أي حقل يُستخدَم للإرسال (found، `F2N.A00`/`A02`)

```text
pollType == QUIZ (correct answer set)              -> pollCreationMessageV5
chat is a community default-subgroup (group_type 3) -> pollCreationMessageV2
else:
  hideParticipantName / endTime / allowAddOption set -> pollCreationMessageV6
  none of those set                                   -> pollCreationMessageV3
```

لا يُملأ `pollCreationMessageV4` أبداً بمسار الإرسال المقروء في هذا التمرير؛ لا يظهر إلا عند الاستلام (§3.3). فحص المجتمع يعيد استخدام نفس شرط `group_type == 3` المستخدَم كحل بديل بالنص الصِّرف للتفاعلات في [WA_MESSAGE_SECRETS.md](./WA_MESSAGE_SECRETS.md) §6.2 (`C0GQ.A0A(chat) == 3`، مضبوط من `isDefaultSubgroup_`)؛ لماذا يحصل استطلاع مجموعة فرعية افتراضية على فتحته المُرقَّمة الخاصة بدلاً من V3/V6 غير مُفسَّر في الكود المقروء هنا (مستنتج: ترتيب طرح تاريخي، بما أن رقم حقل V2 هو الأدنى في المجموعة الموسَّعة).

عملياً: **V3** هي الفتحة الحالية لاستطلاع متعدد/فردي الاختيار عادي بلا إضافات، **V6** هي الحالية لاستطلاع يستخدم وقت الانتهاء أو إخفاء أسماء المصوّتين أو إضافة الخيار، **V5** هي الحالية للاختبارات، و**V2** نسخة خاصة بمجموعة فرعية ضمن مجتمع بنفس الشكل الأساسي. **V1** (الحقل غير المُرقَّم 49) و**V4** لا يختارهما المُرسِل في هذا البناء.

### 3.2 `pollCreationMessageV4` = غلاف تحوُّطي للمستقبل (found، `F2N.CM7`)

نوع بروتو V4 هو `FutureProofMessage` (`BD2`، حقل واحد `message` = `Message` داخلية). عند الاستلام، عندما تكون فتحة V4 مملوءة، يفك العميل غلاف `BD2.message_` ويقرأ حقل `pollCreationMessage` (49) الخاص بتلك الرسالة الداخلية *نفسها* كـ`PollCreationMessage` الفعلي. هذا غلاف تراجعي حقيقي، لا حقل ميت: مُرسِل يحتاج إصدار نسخة استطلاع أحدث/غير مُعرَّفة يمكنه تغليف استطلاع أساسي (بشكل الحقل 49) داخل V4 بحيث لا تزال العملاء الأقدم — التي لا تفهم إلا فكّ غلاف `FutureProofMessage` العام، لا الفتحة الأحدث — تعرض استطلاعاً عادياً. لا يوجد مسار كود في هذا التمرير يملأ V4 عند الإرسال، فهذا موجود لتوافق تقدمي/تراجعي بين إصدارات العميل، لا لأي شيء يُصدره عميل 2.26.41.6 نفسه (مستنتج).

### 3.3 الاختيار من جانب الاستلام والتنازل (found، تقريبي؛ فقد المُفكِّك بعض بنية الفرع)

يفحص `F2N.CM7` حقول بت `Message` بالترتيب V1 ← V2 ← V4 ← V5 ← V6 ← V3-احتياطي ويُحلِّل أي حقل مُرقَّم مملوء إلى نفس المُحقِّق (`F2N.A01`، §4). ثلاثة أعلام تضبط قبول حقول V6 الإضافية عند الاستلام؛ عندما يكون العلم مُعطَّلاً **يُنزَّل** الاستطلاع (يُحلَّل كعنصر نائب تحوُّطي بدلاً من فقاعة استطلاع) بدلاً من رفضه تماماً:

| الحقل الإضافي | البوّابة | الأثر عندما تكون البوّابة مُعطَّلة |
|-------------|------|--------------------------|
| `endTime` | علم AB عددي **24884** (`receivingEnabled`) | يُسجَّل `poll downgraded to FMessageFuture (receiving disabled)`، لا يُعرَض كاستطلاع |
| `hideParticipantName` | علم AB عددي **24885** | تنازل (القطبية الدقيقة للفحص غير محسومة كاملاً من مسار التحكم المُفكَّك) |
| `allowAddOption` | علم AB عددي **25758** | تنازل |

لم يتمكَّن من إعادة بناء التعشيش الدقيق لهذه الثلاثة شروط بالكامل (يُقرِّر JADX كتل مُكرَّرة/غير قابلة للوصول في `F2N.CM7`)؛ أعلام الضبط ونتيجة التنازل مُعثور عليهما، أما التركيبة المنطقية الدقيقة فمستنتجة.

### 3.4 بوّابة محتوى الصورة

لا يُحترَم `pollContentType = IMAGE` إلا في مسار تحليل V3/V5 عندما يكون بت `pollContentType` مضبوطاً؛ إذا كان مضبوطاً لكن القيمة ليست `IMAGE`، تُرفَض الرسالة (`return null`، تسقط إلى المُحلِّل العام) بدلاً من مُعامَلتها كنص صِرف صمتاً.

## 4. تحقق الإنشاء (found، `F2N.A01`)

مُحقِّق واحد مشترَك بين كل حقول الإنشاء المُرقَّمة. يطرح استثناء، رمز خطأ **11** إلا إذا أُشير إلى غيره:

| الفحص | القاعدة | سلسلة الخطأ |
|-------|------|--------------|
| حضور الاسم | يجب ضبط بت `name` | `poll_creation_missing_name` |
| طول الاسم | 1-5000 حرف (إلا إذا تجاوز سياق تحليل متسامح هذا، §4.1) | `poll_creation_invalid_name` |
| إجابة الاختبار الصحيحة | إذا `pollType=QUIZ`، يجب ضبط بت `correctAnswer` | `poll_creation_missing_correct_answer` |
| حضور الخيارات | خيار واحد على الأقل، إلا إذا انطبق الحل البديل لصفر الخيارات (§4.1) | `poll_creation_missing_options` |
| عدد الخيارات (الأدنى) | ≥ 2 خيار (0 ضمن الحل البديل) | `poll_creation_invalid_options_count` |
| عدد الخيارات (الأعلى) | ≤ `min(AB int 1408, 12)` — 12 سقف صلب للعميل بصرف النظر عن قيمة الخادم | `poll_creation_invalid_options_count` |
| طول اسم الخيار | 1-2500 حرف لكل خيار | `poll_creation_invalid_option` |
| اسم الإجابة الصحيحة | إذا كان اختباراً، يجب أن يكون `correctAnswer.optionName` غير فارغ | `poll_creation_missing_correct_answer_name` |
| خيارات مكرَّرة | يجب أن تكون أسماء الخيارات فريدة | `poll_creation_duplicate_options` |
| خيارات مُقتطَعة مكرَّرة | بعلم AB **25758**، يجب أن تكون الأسماء المُقتطَعة من المسافات الزائدة فريدة أيضاً | `poll_creation_duplicate_trimmed_options` |
| الإجابة الصحيحة تطابق خياراً | يجب أن يساوي اسم الإجابة الصحيحة اسم خيار واحد | `poll_creation_unmatched_correct_answer` |
| حضور عدد الاختيار | يجب ضبط بت `selectableOptionsCount` | `poll_creation_missing_selectable_options_count` |
| نطاق عدد الاختيار | `0 <= selectableOptionsCount <= options.size()` (أو `<= min(1408,12)` ضمن الحل البديل) | `poll_creation_invalid_selectable_options_count` |

### 4.1 الحل البديل المتسامح لصفر الخيارات (مسار كود مُعثور عليه، الدلالات مستنتجة)

قيمة منطقية محلية (`z`) محسوبة من علم AB منطقي **37909**، تُستشار فقط عندما يساوي عدّاد سياق تحليل داخلي 1، تُخفِّف الحد الأدنى لعدد الخيارات إلى 0 وتُوسِّع سقف عدد الاختيار إلى الحد الخام `min(1408,12)` بدلاً من `options.size()`. قيمة سياق التحليل التي يتوافق معها ذلك (استلام عادي مقابل مسار استيعاب آخر، مثل مزامنة التاريخ) لم تُحسَم؛ يُسجَّل هذا كمُعثور عليه-لكن-غير مُفسَّر بدلاً من ميزة "استطلاع بلا خيارات" مؤكَّدة وظاهرة للمستخدم.

### 4.2 الحل البديل لمزامنة التاريخ/الاسم المتسامح

علم سياق منفصل (`c33371Eg0.A0W`) يُقصِّر الدائرة لفحص طول الاسم وفحص طول اسم اللقطة النتيجة (في `F39`، §9) بالمعادلة، فيقبل السلسلة الخام دون فحص. يتسق مع مسار تحليل من مصدر موثوق (مثل إعادة استيراد تاريخ محلية) بدلاً من استلام شبكة عادي؛ غير مؤكَّد بشكل مستقل.

## 5. خيارات الاستطلاع الصوري: `pollCreationOptionImageMessage`

### 5.1 البنية والربط (found)

يُغلِّف `pollCreationOptionImageMessage` (الحقل 90) رسالة `ImageMessage` مرفوعة عادية داخل `FutureProofMessage` — الصورة **ليست** مُضمَّنة في `PollCreationMessage.Option`. تُرسَل صورة كل خيار كرسالة فرعية خاصة بها، مرتبطة بالاستطلاع (الذي لم يُرسَل بعد) عبر `MessageContextInfo.messageAssociation`، نوع الارتباط `MEDIA_POLL = 6` (`AnonymousClass122.MEDIA_POLL`؛ قيمة التعداد في هذا البناء — كانت 7 في بناء سابق، القيمة العددية ليست مستقرة عبر الإصدارات ويجب إعادة قراءتها لكل إصدار). مساعد جانب الإرسال "MediaPollAssociationProvider" (في `C20M`) يعدّ صفوف `message_association` لمعرّف صف الاستطلاع الأم ونوع الارتباط `6`؛ بمجرد وصول العدد إلى عدد الخيارات، تُعتبَر كل صور الخيارات مرفوعة ويتابع العميل إرسال الاستطلاع نفسه بـ`pollContentType = IMAGE`.

### 5.2 تجزئة الخيار لخيارات الصور (مستنتج، منقول من بناء سابق، لم يُعَد استخلاصه سطراً بسطر في 2.26.41.6)

للخيارات النصية الصِّرفة يبقى حقل `optionHash` السلكي فارغاً؛ التجزئة الوحيدة المحسوبة لخيار نصي صِرف هي ملخَّص البحث المحلي `C13J.A00`:

```text
optionHash(text option) = Base64(SHA-256(UTF8(optionName)))
```

(مؤكَّد مباشرة في 2.26.41.6، §9.1 — هذه التجزئة هي المُستخدَمة لمطابقة اختيارات التصويت، لا حقل `optionHash` الخاص بالبروتو). لخيارات **الصور** يُملأ حقل `optionHash` الخاص بالبروتو؛ تتبُّع نسخة سابقة لتسلسل الإرسال وجد أنه يجمع تجزئة اسم الخيار مع `fileSha256` الخاص بالصورة المرفوعة:

```text
nameHash   = lowerHex(SHA-256(UTF8(optionName)))
imageHash  = base64(imageMessage.fileSha256)
optionHash = lowerHex(SHA-256(UTF8(nameHash + imageHash)))
```

لم تُعاد التحقق من هذه الصيغة مقابل كود 2.26.41.6 في هذا التمرير (لم يُعثر على الصنف الحاسب)؛ تُحمَل كمستنتجة ويجب إعادة فحصها قبل الاعتماد عليها.

## 6. `pollAddOptionMessage` (`C30556DRc`، الحقل 121)

### 6.1 الحقول (found)

`pollCreationMessageKey` **1** (`MessageKey`)، `addOption` **2** (`PollCreationMessage.Option`)، `metadata` **3** (`PollUpdateMessageMetadata`، نفس شكل التصويت، §7).

### 6.2 الإرسال (found، `F2L.ADr`)

يبني `Option` واحدة من الاسم الجديد (وتجزئته، لاستطلاعات الصور)، يُرفِق مفتاح الاستطلاع الأصلي، و — للدردشات الفردية، عندما لا يكون سياق تحرير — يحل هوية المُرسِل عبر حد LID/PN بنفس الطريقة التي تفعلها طبقة سرّ الرسالة لإضافات أخرى (انظر [WA_MESSAGE_SECRETS.md](./WA_MESSAGE_SECRETS.md) §6.1 الخطوة 4). الخيار *لا* يُشفَّر بسرّه الخاص على هذه الطبقة كما يفعل `pollUpdateMessage`: تنتقل حمولة إضافة الخيار كحقل رسالة عادي؛ ما يُغلَّف في `secretEncryptedMessage` (النوع `POLL_ADD_OPTION`) هو محاولة إضافة الخيار كاملة عندما يجب أن تنتقل عبر مخطط سرّ الرسالة (§8).

### 6.3 تحقق الاستلام (found، `F2L.CM7`)

| الفحص | الخطأ |
|-------|-------|
| بوّابة الميزة: يجب أن يكون علم AB عددي **25758** غير صفري | خطأ **10017** |
| حضور `pollCreationMessageKey` | `poll_add_option_missing_poll_message_key` |
| حضور `addOption` | `poll_add_option_missing_poll_option` |
| اسم خيار غير فارغ، ≤ 2500 حرف | `poll_add_option_invalid_option` |

يُشفَّر الجسم المحلي الناتج بسرّه الخاص للنقل بحالة استخدام `Poll Add Option` (استدعاء مؤكَّد لمساعد سرّ الرسالة بـ`AnonymousClass122.POLL_ADD_OPTION` كوسم ارتباط). تُتبَّع الخيارات المُضافة لمطابقة الخيار الموجود بنفس طريقة خيارات الاستطلاع الصوري (نوع الارتباط `POLL_ADD_OPTION = 18`).

## 7. `pollUpdateMessage` (التصويت وبيانات تعريف التصويت)

التشفير الكامل (حالة استخدام HKDF `Poll Vote`، AAD، AES-GCM، إعادة محاولة هوية LID/PN) موجود في [WA_MESSAGE_SECRETS.md](./WA_MESSAGE_SECRETS.md) §3-§7؛ يغطي هذا القسم فقط ما تفعله معالِج التصويت على الاستطلاع (`DUA`، يرث `F2P`) بالنص الصِّرف.

### 7.1 مساران للإرسال/الاستلام (found)

يختار علم AB منطقي **6772** بين:
- **مُفعَّل** (الحالي): مساعد تشفير مشترَك (`C33285Eeb`) يبني نص التشفير ومفتاح `MessageKey`؛ يُعاد محاولة التصويت من زوج `(iv, payload)` مخزَّن سابقاً عند وجوده بدلاً من إعادة التشفير.
- **مُعطَّل** (قديم): فرع مضمَّن في `DUA` يقوم بنفس استدعاء HKDF/AES-GCM مباشرة، مُستخلِصاً هوية المُرسِل الهدف نفسه (LID الخاص للتصويتات على استطلاع المصوِّت نفسه، وإلا JID المُحلَّل لهدف التصويت).

### 7.2 حمولة التصويت: `PollVoteMessage` (`DPF`)

حقل واحد `selectedOptions` **1**، بايتات مُكرَّرة — كل إدخال هو ملخَّص SHA-256 بطول 32 بايت لاسم الخيار (§9.1)، لا فهرس. يفحص `MessageAddOnPollVoteUtils` (`AbstractC33199EdC`) الاختيار المفكوك التشفير:

| الفحص | القاعدة | وسم السجل |
|-------|------|---------|
| حجم الاختيار | ≤ 12 **و** ≤ `selectableOptionsCount` الخاص بالاستطلاع (عندما > 0) | `poll_vote_invalid_options_count` |
| شكل التجزئة | كل تجزئة مختارة تُفكَّك إلى 32 بايت تماماً | `poll_vote_invalid_option_hashes` |
| التكرارات | لا تجزئة مُكرَّرة في تصويت واحد | `poll_vote_duplicate_option_hashes` |
| الحل | يجب أن تطابق كل تجزئة مختارة واحدة من تجزئات خيارات الاستطلاع المعروفة (غير المحذوفة) | تُعيد نتيجة خطأ، لا تطابق -> يُرفَض التصويت |

### 7.3 وقت الانتهاء وبيانات التعريف (found، `DUA.A01`)

يُرفَض تصويت يكون `senderTimestampMs` الخاص به بعد `endTime` الاستطلاع (`poll_update_past_end_time`)؛ بعلم AB منطقي **2321** يُغذِّي حدث تصويت مرفوض إضافة إلى ذلك عدّاد قياس عن بُعد (`N0e`). تُختَم `metadata` التصويت (`pollNameHash`، `lastEditStanzaId`) عند الإرسال فقط بعلم AB منطقي **31593**؛ عند الاستلام، تُسجَّل كتلة بيانات تعريف غائبة/فارغة كـ`"unstamped"` (لا تُرفَض بنفسها) بينما خاتم *غير مطابق* (يفحصه `C32977EZa`) يُسقِط التصويت بـ`poll_update_tc_drop`. توجد هذه البيانات لتتيح لعميل اكتشاف أنه يصوّت على استطلاع لم يُلاحق تاريخ تحريره بعد.

## 8. تحرير الاستطلاع (`secretEncryptedMessage`، `secretEncType = POLL_EDIT`)

يُحمَل داخل غلاف `secretEncryptedMessage` العام (الحقل 82)، لا ناقل خاص بالاستطلاع؛ انظر [WA_MESSAGE_SECRETS.md](./WA_MESSAGE_SECRETS.md) §5/§7.4 للغلاف وAAD وجدول رموز الخطأ (`poll_edit_message_stanza_invalid`، بوّابة علم AB عددي **24886**، خطأ **10016**). يتطلب التحقق الخاص بالاستطلاع (`F3Y`، `SecretEncryptedMessageDeserializationValidator`):

- أن تكون الرسالة الداخلية من نوع FMessage 66 وأن تكون استطلاعاً قبل التحرير وبعده كليهما؛
- أن تبقى `endTime`، `hideParticipantName`، `allowAddOption`، `selectableOptionsCount` و`pollType` **غير مُغيَّرة** بين الاستطلاع المخزَّن والمُحرَّر — فقط نص السؤال و/أو نصوص الخيارات قد تختلف؛
- مطابقة الخيار: بعلم خاص بالدردشة (`EOI.A01()`، المعرّف غير محسوم) مُفعَّل، تُطابَق الخيارات المُحرَّرة مع سجل إعادة تسمية مخزَّن عبر مطابقة متسلسلة (حافظة للترتيب)، تسمح بإعادة تسمية الخيارات في مكانها؛ السلوك الدقيق لفرع المقارنة غير المُعيد التسمية مستنتج (يُسقِط JADX مرة أخرى جزءاً من مسار التحكم — تسقط الدالة إلى `poll_edit_invalid_edits` في ذلك الفرع بالشكل المُفكَّك، وهذا غير مرجَّح أن يكون السلوك الحقيقي للعميل لتحرير بلا تأثير).

توجد سلسلة toast "Couldn't edit poll" في الموارد، مؤكِّدة أن تحرير الاستطلاع ظاهر للمستخدم في هذا البناء، لا مجرد مسار بروتوكول محجوز.

### 8.1 واجهة تحرير الاستطلاع (جديدة في 2.26.45.10) — عملية السلك غير محسومة

تشحن حزمة جديدة `com.whatsapp.polls.ui.edit` `PollEditActivity` إضافة إلى حوارات
مساعدة (`PollEditDiscardChangesDialog`، `PollEditSendFailedDialog`،
`PollOptionRemoveConfirmationDialog`)، تتيح للمُرسِل إعادة تسمية استطلاع مُرسَل أصلاً أو
إضافة/إزالة خيارات منه. مُعثور عليه وغير معروف، من تتبُّع smali ساكن (لا فك تجميع
بما يتجاوز قراءة smali الموجود):

- **مُعثور عليه:** `PollEditActivity` مدعومة بحالة تحرير محفوظة بـ`SavedStateHandle`
  (نموذج عرض `LX/8kp`، حمولة تحرير `LX/A4G`: الاسم/المعرّف، سلسلة اسم الاستطلاع، صفوف الخيار
  الحالية، `Set<Long>` من معرّفات الصفوف المحذوفة). صفوف الخيار (`LX/JZ8`) لا تحمل علم
  حذف — الخيار غائب ببساطة عن القائمة النهائية المُفرَّقة مقابل حالة الاستطلاع الحية
  (`LX/8kp;->A03(LX/A4G;LX/9ei;LX/8kp;)LX/9oc;`). إزالة الخيار مضبوطة بفحص طرح
  متدرِّج، `LX/Ihb;->getPollRemoveOptionRollout()LX/1yG;` — بوّابة ميزة من جانب العميل،
  لا دليل على عملية سلك جديدة.
- **مُعثور عليه:** فرق المخطط البروتوي بين 2.26.41.6 و2.26.45.10 يحتوي **صفر**
  تغييرات متعلقة بالاستطلاع — لا حقل جديد أو مُعاد تسميته لإعادة التسمية أو إزالة
  الخيار يظهر في أي مكان من المخطط المُستخرَج لهذا الإصدار.
- **مستنتج:** إضافة خيار من هذه الواجهة على الأرجح لا تزال تنتقل عبر
  `pollAddOptionMessage` الموجود (§6، الحقل 121) — ملمح "إضافة صف" في الواجهة يطابق شكل
  تلك الرسالة ولم يُدخَل بديل أولي لإضافة خيار. غير مؤكَّد بتتبُّع معالِج الحفظ.
- **غير معروف:** إعادة التسمية وإزالة الخيار بلا أولية سلك مؤكَّدة. مرشَّحان
  غير مؤكَّدين، ولا أحدهما أكثر احتمالاً من الآخر بالدليل الحالي: (1) استبدال استطلاع
  كامل عبر `Message.editedMessage` (`FutureProofMessage` تُغلِّف `pollCreationMessage`
  جديدة)، أو (2) إعادة استخدام حقل `vote` المشفَّر الغامض لـ`pollUpdateMessage`
  (`PollEncValue`، §7) لتحديث ليس تصويتاً. استدعاء الشبكة الفعلي لزر الحفظ
  يقف خلف موزِّع `View.OnClickListener` مشترَك ومُدمَج بـR8 (`LX/A50`) لا يمكن
  عزل فرع `switch` الخاص به من smali وحده — هذا هو العائق المحدَّد، لا اختيار نطاق.

تُترَك هذه مفتوحة بدلاً من حسمها بأفضل تخمين؛ يُعاد الفحص متى أظهر فرق بروتو مقابل
إصدار لاحق حقلاً جديداً، أو متى تُعقِّب فرع توزيع `LX/A50`.

### 9.1 تجزئة الخيار (found، `C13J.A00`)

```text
optionHash = Base64(SHA-256(UTF8(optionName)))
```

SHA-256 صِرف لنص الخيار الظاهر، دون مادة مفتاح. هذه القيمة المخزَّنة لكل خيار محلي (`C33283EeZ.A02`) والقيمة التي تُطابَق مقابلها إدخالات `selectedOptions` الخاصة بتصويت. أي تطبيق يعرف نص الخيار يستطيع حساب نفس التجزئة — خصوصية التصويت تأتي بالكامل من تشفير سرّ الرسالة لحمولة التصويت (§7، و[WA_MESSAGE_SECRETS.md](./WA_MESSAGE_SECRETS.md))، لا من كون التجزئة غير قابلة للتخمين.

## 11. التصويت المتعدد مقابل الفردي

`selectableOptionsCount` (الحقل 4) هو الآلية الوحيدة: يُرفَض تصويت باختيارات أكثر من هذه القيمة (§7.2). لا توجد قيمة منطقية منفصلة "هل متعدد الاختيار" على السلك — الاختيار الفردي هو ببساطة `selectableOptionsCount = 1`. تُعرِض واجهة الإنشاء هذا كمفتاح تبديل واحد، **"السماح بإجابات متعددة"** (سلسلة `str425f`)؛ عند إيقافه يُستنتَج أن العميل يرسل `selectableOptionsCount = 1`، عند تفعيله يُستنتَج أنه يرسل `selectableOptionsCount = options.size()` (لا يبدو أن الواجهة تعرض سقفاً عددياً حراً — مستنتج من سلسلة منطقية واحدة، غير مؤكَّد بشكل مستقل في كود واجهة الإنشاء). يسمح البروتوكول نفسه بأي قيمة `0..options.size()` (§4)، فقيمة من جانب العميل غير 1 أو "كل الخيارات" ممكنة حتى لو لم تعرضها الواجهة الجاهزة. الاختبارات أحادية الاختيار ضمنياً (إجابة صحيحة واحدة؛ سلسلة ظاهرة للمصوِّت "Quiz • Select one correct answer"، `str57a5`).

تؤكِّد التسميات الظاهرة للمصوِّت النموذجين: `"Select one"` (`str3865`) مقابل `"Select one or more"` (`str3866`).

## 12. `pollResultSnapshotMessage` / `V3`: لقطة إعادة التوجيه

### 12.1 الغرض (found، `F1A`)

إعادة توجيه استطلاع حيّ إلى دردشة أخرى **لا** يُعيد توجيه الاستطلاع التفاعلي. يُحوِّل `F1A` (أحد عدة مُحوِّلات "إعادة توجيه" تنفّذ كلها نفس واجهة التحويل المُستخدَمة عبر أنواع الرسائل — المُحوِّل الشقيق للأنواع غير المدعومة يطرح `"Cannot forward message of type: ..."`) الاستطلاع الحي (`C13J`) إلى جسم `Dd2`: نص السؤال، اسم كل خيار و**عدد التصويت المحلي الحالي**، ونوع الاستطلاع/الاختبار. يُسلسَل هذا بعد ذلك كـ`pollResultSnapshotMessage` (استطلاع عادي) أو `pollResultSnapshotMessageV3` (اختبار) ويُعرَض بحامل عرض مخصَّص (`DWH`)، متمايز عن فقاعة الاستطلاع التفاعلية.

### 12.2 الحقول (found، `DSF`)

`name` **1** (string)، `pollVotes` **2** (`PollVote` مُكرَّرة — `optionName` **1**، `optionVoteCount` **2**)، `contextInfo` **3**، `pollType` **4** (نفس تعداد `PollType` الخاص بالإنشاء).

### 12.3 التحقق (found، `F39`)

نفس شكل فحوصات الإنشاء: اسم 1-5000 حرف، خياران على الأقل، بحد أقصى `min(AB 1408, 12)` خيارات، اسم كل خيار 1-2500 حرف. لنسخة **الاختبار** (`V3`)، تُفرَض عدادات التصويت إلى 0 عند الإرسال — لقطة اختبار مُعاد توجيهها لا تكشف أبداً عن النتائج، بل السؤال وقائمة الخيارات فقط.

- استخلاص HKDF وسلاسل حالات الاستخدام `Poll Vote`، `Event Response`، `Enc Comment`، `Enc Reaction`، `Event Edit`، `Message Edit`، `Poll Edit`، `Poll Add Option` تطابق سلاسل عميل أندرويد الحرفية تماماً، بما فيها AAD من نوع `id\0modifier` لـ`Poll Vote`.
- AAD، إعادة محاولة الهوية (PN/LID)، ومعالجة السرّ الغائب (العودة إلى التحديث الخام غير المفكوك التشفير) تطابق سلوك أندرويد الموصوف في هذا التقرير (§7) وفي [WA_MESSAGE_SECRETS.md](./WA_MESSAGE_SECRETS.md) §7.2-§7.3.
- لم يُعثر على أي مسار تشفير من جانب الإرسال لـ`pollUpdateMessage` (أو `encReactionMessage`، `encEventResponseMessage`، `encCommentMessage`) في الملفات المقروءة — أي أن ذلك التنفيذ استطاع فكّ تشفير تصويت وارد لكن الملفات المُراجَعة لم تحتوِ كوداً لتشفير وإرسال تصويت.

لا شيء خاص بالاستطلاع بما يتجاوز ما ذُكر هناك أصلاً أُعيد التحقق منه بشكل مستقل في هذا التمرير (لم يُقرأ كود Baileys لإنشاء الاستطلاع، تجزئة الخيار، أو تحرير الاستطلاع)؛ لا زعومات Baileys إضافية تُطرَح هنا.

## 17. فروق أساسية

| هذا | لا هذا |
|------|----------|
| `pollCreationMessage`/V2/V3/V5/V6 (نوع `PollCreationMessage`) | `pollCreationMessageV4` (`FutureProofMessage` تُغلِّف استطلاعاً أساسياً داخلياً) |
| `pollUpdateMessage` (تصويت، أو بيانات تعريف تصويت) | `secretEncryptedMessage` بـ`secretEncType=POLL_EDIT`/`POLL_ADD_OPTION` (تحرير الاستطلاع / إضافة خيار) |
| `pollAddOptionMessage` (حمولة الخيار الجديد) | غلاف `secretEncryptedMessage` الذي يحملها على السلك عندما تكون مرتبطة بسرّ الرسالة |
| `pollResultSnapshotMessage`/V3 (ثابتة، مُعاد توجيهها) | الاستطلاع التفاعلي الحيّ (`pollCreationMessage*`) |
| اختيار الخيار بتجزئة SHA-256(name) | الاختيار بالفهرس — استطلاعات WhatsApp لا تختار أبداً بالموضع |
| `hideParticipantName` (إعداد عرض في الواجهة) | إخفاء هوية مُرسِل التصويت (لا وجود له؛ يحل المُنشئ هوية المصوِّت دائماً) |
| `selectableOptionsCount` (الإشارة الوحيدة لمتعدد/فردي الاختيار) | قيمة منطقية منفصلة "هل متعدد الاختيار" (لا وجود لها) |

## 18. التدفق الكامل (الإنشاء، خيار الصورة، التصويت، إعادة التوجيه)

```
[Creator]                                          [Server]                     [Participant]
   │ build PollCreationMessage                        │                              │
   │  (quiz? -> V5; community subgroup? -> V2;         │                              │
   │   extras(endTime/hide/addOpt)? -> V6; else V3)    │                              │
   │ [image poll]                                      │                              │
   │  send N × pollCreationOptionImageMessage           │                              │
   │   (messageAssociation MEDIA_POLL=6, parent key)───▶───────────────────────────▶ received,
   │  wait for all fileSha256                           │                              associated
   │  compute optionHash per option                     │                              │
   │ send pollCreationMessage* ─────────────────────────▶──────────────────────────▶ store poll,
   │                                                    │                              secret
   │                                                    │        select option(s)     │
   │                                                    │        hash = SHA256(name)  │
   │                                                    │        key = HKDF(secret,   │
   │                                                    │          pollId‖creator‖    │
   │                                                    │          voter‖"Poll Vote") │
   │                                                    │        pollUpdateMessage    │
   │◀────────────────────────────────────────────────────◀ {key, vote{ct,iv}, ts} ────│
   │ validate: end time, selection count/hash shape     │                              │
   │ decrypt, resolve hash -> known option              │                              │
   │ apply vote                                         │                              │
   │                                                    │                              │
   │ [user forwards the poll elsewhere]                 │                              │
   │ convert live poll -> Dd2 (name, per-option count)  │                              │
   │ quiz? zero the counts                              │                              │
   │ send pollResultSnapshotMessage[/V3] ───────────────▶──────────────────────────▶ static bubble,
   │                                                    │                              not interactive
```
